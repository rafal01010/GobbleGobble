# Review-source feasibility decision

GG-009.01B is complete as of 2026-10-24 in Asia/Manila. Dependency GG-002.06 is checked. Actual Google extraction and a bounded Google-to-model pilot passed. The user explicitly removed legal clearance as a completion gate and reaffirmed full application quality. Production-quality engineering remains required. This decision does not pass GG-003 or replace Google as primary.

## Decision

Treat Google billing as unavailable. During this task, the user reported an unsuccessful BDO debit-card attempt and instructed us to assume no Google billing. Their report of similar Reddit posts was not independently verified. Billing country, the original error, and issuer rejection details remain unknown. No billing account or payment method was inspected or changed.

Official billed Google products do not provide a usable path for this project now. A bounded anonymous probe of an existing extractor's protocol fetched 30 distinct review records with text across two pages in 2.935 seconds. It required no API key, billing, cookies, or browser access. The reviewed sources still do not establish all rights needed for automated review-to-LLM recommendations, generated findings, and durable results. Technical extraction and supported downstream use are separate findings.

The closest review-specific CLI initially found was `dahliasan/google-reviews-pp-cli`. The selected application path instead adapts `YasogaN/google-maps-review-scraper` 3.1.0 into the Python and HTTPX client. The actual YasogaN package ran successfully through its public entry point. Subsequent temporary comparisons with signed-in `google-reviews-scraper-pro` returned the same 20 newest review IDs, order and ratings for Toyo Eatery and Ippei Honten. Pro supplied no extra substantive review text and took about 15 and 23 times longer. The user rejected Pro and requested removal of its temporary code. [The comparison record](GOOGLE_REVIEW_PROBES.md#temporary-signed-in-pro-comparison) links the retained outputs and limitations. The prepared OpenAI research route also ran successfully once, but returned third-party mentions rather than demonstrated direct Google review access. Local configuration now passes preflight. No further configuration is needed to repeat the anonymous extraction approach.

The user reaffirmed that Google reviews are mandatory and primary. Independent food evidence may supplement Google reviews but cannot replace them or satisfy the Google review requirement. The proposed independent-primary amendment was rejected and must not be applied. Wikivoyage is explicitly excluded from source candidates by the user because it is out of date. Its experiment is historical evidence only and does not authorize supplementary use. Its 2017 listing does not establish current restaurant quality, freshness or crowd sentiment. The remaining work concerns the supported Google review-to-recommendation path. A copied Google review obtained through another channel does not become independent evidence.

## A yt-dlp-like tool and building our own

`google-reviews-pp-cli` is the closest interface match found. It accepts a Maps URL containing a feature ID, supports JSON output and requested sorting, and follows continuation tokens. Its README documents a roughly 300-review pagination failure and missing business-name search. The inspected repository was created in May 2026 and had two stars, so this is a small candidate rather than evidence of yt-dlp-level maturity. [Repository and limitations](https://github.com/dahliasan/google-reviews-pp-cli).

The inspected revision is `80577f33d510ca699f4626b0c8946aa461493f91`. Its review path calls `GetLocalBoqProxy`, strips Google's anti-XSSI prefix, then parses positional JSON arrays. The `--lang` and `--country` review flags are accepted but unused in this path. Cookie loading automatically invokes `agent-browser` when an environment override is absent. Our probe did not run that code or access any cookies. [Review implementation](https://github.com/dahliasan/google-reviews-pp-cli/blob/80577f33d510ca699f4626b0c8946aa461493f91/internal/cli/reviews.go).

The isolated Python probe reproduced the anonymous request and inspected only structural metadata. Both requests returned HTTP 200. Page one contained 10 records and page two contained 20. All 30 had distinct IDs, nonempty text fields, and ratings between one and five. The pages had no overlapping IDs and each returned a changed continuation token. This validates one continuation step. It does not validate the CLI binary, full history, ordering, original versus translated text, freshness, author accuracy, or our target restaurant branches. The second-page protocol omits the requested page size, so local truncation and accounting are necessary. No review text, author data, response body, IDs, or cursor values were persisted or sent to a model.

`gosom/google-maps-scraper` is the broader alternative. It uses browser automation, accepts Maps URLs, and documents extended review extraction. Its latest release observed here was v1.18.1, published 2026-09-20. It was not run. A separate pure-HTTP Python project explicitly reports that signed-out review text can be unavailable in some regions. Our successful anonymous sample does not disprove that limitation elsewhere. [Gosom repository](https://github.com/gosom/google-maps-scraper), [Python extractor limitations](https://github.com/sonagara-vashram/google-maps-scraper).

Building a small extractor from scratch is technically feasible. The live protocol probe already demonstrates the difficult access premise without Google billing. A review-only implementation would need these components:

- A matched branch input with Maps URL and feature ID. Ambiguous or absent matches must remain explicit. This is separate from geographic discovery.
- A bounded anonymous HTTP transport and a parser that rejects unfamiliar response layouts. Requested sort, locale, retrieval time, and observed sample size belong in the result.
- Cursor pagination with deduplication, maximum records, requests, bytes, and elapsed time. A partial sample must remain distinguishable from exhausted history, empty results, and failed access.
- A source-use boundary before any model call, display, storage, or tracing. Parser success cannot supply that policy decision.
- Real branch samples across intended regions, plus repeatable parser fixtures only where retention is supported. Upstream changes will require maintenance.

GG-002.06A subsequently prepared the bounded Google review client from the demonstrated anonymous route, including branch matching, partial and failure states, source admission and prepared gate scenarios. The earlier proposed adapter evaluation GG-009.01B2 was folded into that existing task rather than added to the queue. After the later Pro comparisons, the user chose the YasogaN-based anonymous client alone and declined scraper backups for now. Pro's temporary code, runtime and throwaway profile were removed. `google-reviews-pp-cli` remains historical research evidence, not an installed backup. A general downloader, complete-history promise, cookie access and browser fallback remain outside the selected scope.
